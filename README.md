# CampusRent

**이용 목적에 맞는 교내 시설·장비 추천 및 대여·예약 관리 시스템**

> 정보시스템프로젝트캡스톤디자인 | New-Era 팀  
> 분석·설계 문서를 기반으로 실제 시스템 구현을 준비하는 프로젝트입니다.

## 1. 프로젝트 소개

CampusRent는 학생이 필요한 교내 시설·장비를 **직접 검색**하거나, **활동 목적과 참여 인원 등에 맞는 추천**을 받아 적합한 자원을 선택하고 대여·예약을 신청할 수 있도록 지원하는 웹 기반 정보시스템입니다. 관리자는 신청 승인·거절, 장비 출고·반납, 시설 이용 상태 등을 관리합니다.

**핵심 차별점은 목적 기반 탐색입니다.** 예를 들어 학생이 '학생회 회의 6명' 또는 '과제 영상 촬영'을 입력하면, 등록된 용도·키워드·인원 조건에 따라 적합한 공간과 장비, 추천 이유를 안내합니다. 필요한 자원을 이미 알고 있다면 이름이나 분류로 직접 검색할 수도 있습니다.

> 목적별 추천은 현재 계획서상 **규칙 기반**이며 별도의 AI 추천 모델을 사용하지 않습니다. 실제 학교 자원 및 운영 정책은 확인이 필요한 부분이 있고, 현재 시연 데이터에는 가상 시설·장비가 포함됩니다.

## 2. 프로젝트 목표

- 이용 목적과 인원에 맞는 시설·장비를 추천하고 추천 이유를 제시
- 시설·장비 직접 검색, 상세 정보 및 이용 조건 확인 지원
- 이용 불가 시 다른 일정 또는 대체 시설·장비 조회 지원
- 선택 목록에서 필요한 항목과 조건을 확인한 뒤 개별 신청
- 관리자 승인·거절, 장비 출고·반납·점검 및 시설 이용 이력 관리

## 10. 화면 구현 및 실행

제공된 Figma Make ZIP을 바탕으로 홈, 장비·시설 검색, 목적별 추천, 선택 목록, 로그인·회원가입, 학생 신청 현황·과거 내역, 관리자 승인·출고·반납·시설 이용 화면을 HTML·CSS·JavaScript로 구현했습니다. 현재는 Spring Boot가 화면과 API를 제공하고 Oracle에서 계정·자원·신청·검수·상태 이력을 조회·저장합니다. HTML의 Thymeleaf용 속성은 준비되어 있지만 Thymeleaf 엔진은 사용하지 않습니다.

JDK 8의 `java`, `javac`가 PATH에 등록되어 있고 Git에서 제외된 `src/main/resources/application-local.properties`에 DB 접속 정보가 있다면 저장소 루트에서 실행합니다. Maven은 최초 실행 시 `.work/`에 준비하며 첫 빌드에는 인터넷 연결이 필요합니다.

```powershell
.\run-server.cmd
```

브라우저에서 [로컬 화면](http://127.0.0.1:8080/)을 확인합니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 서버가 이미 실행 중이면 주소만 열면 됩니다.

| 구분 | 시연 이메일 | 시연 비밀번호 |
| --- | --- | --- |
| 학생 | demo@campusrent.example | Campus123! |
| 다른 학생 | other@campusrent.example | Campus123! |
| 관리자 | admin@campusrent.example | CampusAdmin123! |

학생으로 로그인해 신청한 뒤 로그아웃하고 관리자 계정으로 로그인하면 [관리자 화면](http://127.0.0.1:8080/admin)에서 승인·출고·반납을 시연할 수 있습니다. 로그인 직후 자동 신청하지 않으며, 최종 확인 창에서 별도 제출합니다.

`preview.cmd`도 같은 백엔드를 실행합니다. 서버를 재빌드할 때는 실행 중인 서버를 먼저 종료하세요. Windows에서는 실행 중인 JAR를 덮어쓸 수 없습니다.

선택 목록은 탭의 `sessionStorage`에 남고, 가입 계정·신청·검수·반납·이력은 **Oracle에 저장**됩니다. 로그인은 HttpOnly 쿠키 기반 서버 세션으로 유지되며 로그아웃·세션 만료·서버 재시작 시 다시 로그인합니다. 이전 IndexedDB 시연 데이터는 자동으로 Oracle에 가져오지 않습니다. 자세한 API와 검증 방법은 [백엔드 안내](docs/backend.md)를 참고하세요.

## 11. Oracle 11g XE 구축 SQL

[db/oracle11g](db/oracle11g/README.md)에 ERD 기준 테이블 26개·컬럼 185개, 시퀀스 17개, 제약조건·인덱스, 초기 관리자·학생 계정과 장비·시설 데이터를 작성했습니다. [화면 매핑](db/oracle11g/mapping.md), 화면별 조회·처리 예시와 승인 프로시저, 개발용 설치·검증 SQL을 포함합니다.

Oracle 접속과 `SELECT 1 FROM DUAL` 시험에 성공했으며, 2026-11-16 테이블 26개·컬럼 185개·시퀀스 17개와 관련 인덱스를 실제 DB에 생성·검증했습니다. 이후 초기 계정 3개·장비 7개·시설 5개 등의 데이터를 입력하고 Spring Boot·화면과 연동했습니다. 승인은 Java 서비스의 DB 트랜잭션으로 구현했으며 `08_approve.sql` 프로시저는 생성하지 않았습니다. 대화와 작업 경과는 [2026-11-16 작업 기록](docs/worklogs/2026-11-16-session.md)에 정리했습니다.

## 12. 관리자 관리 기능 및 안정성 검증

관리자로 로그인하면 [장비 관리](http://127.0.0.1:8080/admin/equipment), [대체 장비 관계](http://127.0.0.1:8080/admin/alternatives), [시설 운영 관리](http://127.0.0.1:8080/admin/facilities)를 사용할 수 있습니다. 등록·수정·이용 중지와 운영 조건·제한 일정 변경은 Oracle에 저장됩니다. 기존 승인 예약에 충돌하는 변경은 차단하고 출고 스냅샷·처리 이력을 보존합니다.

동시 승인·부분 저장 실패 롤백·실제 서버 재시작 후 영속성을 검증했습니다. 상세 시험 결과, 남은 범위와 검증 자원이 남는 방식은 [2026-11-18 작업 기록](docs/worklogs/2026-11-18-session.md)을 참고하세요.

후속으로 [품목·모델·사양 관리](http://127.0.0.1:8080/admin/models), 시설 제한 해제·변경 전후 이력, 신청 경로·최초 희망 조건 저장을 추가했습니다. 기존 객체 이름은 유지하며 시설 제한 이력용 증분 SQL 10번을 별도로 적용했습니다. 원본 ERD 이후 확장은 [DB 매핑](db/oracle11g/mapping.md)에 구분합니다.

현재 요구사항별 구현·미구현 범위는 [대응표](docs/requirements-status.md), 실제 참여자 검증 절차는 [사용자 시험](docs/usability-test.md), 패키징과 서버 설정 예시는 [배포 안내](docs/deployment.md)를 참고하세요. 실제 사용자 시험과 외부 서버 배포는 아직 진행하지 않았습니다.

관리자 반납 검수에서 구성품별 손상·메모를 저장하고, 학생 본인·관리자의 **출고·검수 회차 상세**에서 반환 이력을 확인할 수 있습니다. 손상 장비는 자동 점검 처리합니다. 승인된 장비 신청에는 **사후 출고 등록** 버튼으로 실제 시각·사유·당시 전달 수량·상태를 기록할 수 있습니다. 기존 ERD 컬럼을 사용하며 추가 테이블 생성은 필요 없습니다.

운영 보완으로 로그인·가입 시도 제한, 비밀번호 변경·세션 종료, 시연 계정 운영 차단, DB 대기 시간 제한·오류 구분, 동일 신청 키의 재시도 중복 방지, 신청 이력 페이지 처리와 live/ready 상태 검사를 추가했습니다. [운영 안내](docs/operations.md)에 검증 범위와 실제 배포·백업·업그레이드 잔여 작업을 구분했습니다. 로컬 시연 계정의 실제 비밀번호·권한은 임의로 바꾸지 않았습니다.

추천은 기존 목적을 유지하며 **영상 콘텐츠 촬영·면접 연습·과제·학습**을 추가했습니다. 유튜브·브이로그·쇼츠·레포트·자료 조사·캡스톤·졸업 작품 등 확장 표현과 부정·복합 문맥을 처리하고 Oracle의 키워드·장비 규칙을 사용합니다. 관리자는 [추천 키워드](http://127.0.0.1:8080/admin/recommendations)에서 인식 표현을 추가·수정·해제할 수 있습니다. [추천 안내](docs/recommendations.md)에 예문·시설 허용 범위·초기 데이터 적용 방법을 정리했습니다.
