# 배포 준비 및 실행 절차

2026-11-18 기준 배포 패키지와 설정 예시를 준비했습니다. 외부 서버에는 설치하지 않았습니다. 서버 OS·접속 방법·도메인·인증서·운영 DB 권한을 받은 뒤 해당 환경에 맞춰 확정합니다.

## 패키지 만들기

실행 중인 프로젝트 서버를 종료한 뒤 저장소 루트에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package-release.ps1
```

이미 빌드한 JAR를 묶을 때는 `-SkipBuild`를 사용합니다. `.work/releases/` 아래 ZIP에 JAR, SHA256, 배포·운영 문서, `ops/`의 세 가지 설정 예시와 읽기 전용 복구 검증 SQL만 포함합니다. 실제 DB 설정·소스·SQL 설치 파일은 포함하지 않습니다. 패키징은 기능 시험을 대신하지 않습니다.

## 서버별 확인 항목

1. 현재 개발 호환 기준은 Java 8, Spring Boot 2.7.18, ojdbc6 11.2.0.4, Oracle 11g XE입니다. 개발 PC의 Java 8u151을 운영 서버에 그대로 복제하지 않습니다. 외부 공개 전 패치된 런타임·프레임워크 유지보수 및 Oracle/JDBC 업그레이드 가능 범위를 별도로 검토하고 회귀 검증합니다. 현재 구성을 운영 보안 승인 완료로 간주하지 않습니다.
2. 애플리케이션 전용 OS 계정, 읽기 전용 JAR 경로와 별도 비밀 설정 경로를 준비합니다. Linux 예시는 `ops/campusrent.service.example`입니다. Windows 서버라면 서비스 등록 방식부터 별도 확정합니다.
3. `ops/application.example.properties`를 Git 저장소 밖의 `/etc/campusrent/application-runtime.properties`로 복사하고 실제 URL·계정·비밀번호를 서버에서 직접 입력합니다. 파일은 서비스 계정만 읽게 설정합니다. `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` 환경변수도 지원합니다. 비밀번호를 명령행 인자로 전달하지 않습니다.
4. 애플리케이션은 127.0.0.1:8080에 바인딩합니다. Linux Nginx 예시에 실제 도메인과 인증서 경로를 채우고 설정 검사 후 활성화합니다. 외부 요청의 전달 헤더는 프록시가 덮어쓰며 애플리케이션 포트를 직접 공개하지 않습니다. HTTPS에서 Secure 세션 쿠키를 사용합니다.
5. DB 방화벽 접근, 최소 권한, 백업·복구 담당자와 복구 절차를 확인합니다. `spring.sql.init.mode=never`를 유지하고 서비스 시작 시 설치 SQL을 자동 실행하지 않습니다. 기존 DB에는 `install_dev.sql`을 재실행하지 않습니다. 10번 마이그레이션 적용 여부는 11번 검증 SQL로 확인합니다.
6. 공개 전에 시연 관리자·학생 계정 비밀번호 교체, 실제 관리자 지정, 시연 자산 중지 여부를 확인합니다. 로그인 시도 제한·계정 복구 정책·학교 개인정보 보관 정책과 부하·장애 시험은 운영 담당자와 확정해야 합니다.

production 프로필은 시연 계정 차단·Secure 쿠키·loopback 바인딩을 검사합니다. 운영 관리자의 이름·이메일을 확정하고 본인이 12자 이상 비밀번호로 가입한 계정의 역할을 별도로 지정한 뒤, 재로그인과 관리자 작업을 검증합니다. 시연 관리자 이메일을 운영 계정으로 재사용하지 않습니다. 실제 계정 지정·비밀번호 교체는 아직 하지 않았습니다. 로그인 제한·비밀번호 변경·상태 검사·백업 절차의 구현 범위는 [운영 안내](operations.md)를 참고하세요.

## 배포 후 확인

- SHA256을 비교하고 서비스 로그에 비밀번호·SQL 바인딩 값이 노출되지 않는지 확인합니다.
- HTTPS 홈, `/api/session`, `/api/catalog`를 조회합니다. 카탈로그는 실제 Oracle 조회이므로 DB 연결도 확인합니다. 응답에 설정값·DB 계정은 포함하지 않습니다.
- 승인받은 시험 자원으로 로그인→신청→승인→출고→반납, 시설 이용, 관리 편집을 확인합니다. 재시작 후 이력이 유지되는지 확인합니다.
- 외부에서 8080 포트 직접 접근이 막히고 HTTPS 세션 쿠키가 Secure·HttpOnly인지 확인합니다.

## 되돌리기

이전 JAR·SHA256·설정 버전을 보존하고 서비스 중지→이전 JAR 복원→서비스 시작→조회 확인 순서로 진행합니다. 세션은 재시작으로 만료됩니다. DB 마이그레이션은 JAR 복원으로 취소되지 않습니다. 10번은 추가형 변경이므로 이전 앱을 복원하면 해제된 제한을 잘못 취급할 수 있어 해당 앱과의 호환성을 먼저 확인해야 합니다. 데이터 삭제나 역방향 DDL은 자동 실행하지 않고 별도 백업·검토 절차로 진행합니다.
