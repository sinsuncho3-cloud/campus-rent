# 사용자 과업 검증

이 문서는 시험 절차와 결과 기록 양식입니다. 사용자가 과업 시험을 일부 진행했다고 알려주었으나 실제 참여자·과업별 결과·추천 효과 수치는 전달받지 않아 임의로 기입하지 않았습니다. 추가 시험에서는 학생 역할 2명 이상과 관리자 역할 1명을 모집하고 설명·동의 후 진행합니다. 자동 브라우저 검사 결과를 사용자 시험 결과로 대신하지 않습니다.

진행자는 가상 시험 자산·시험용 계정을 준비하고 개인정보·DB 비밀번호를 기록하지 않습니다. 학생은 서로 다른 계정을 사용합니다. 과업 시작부터 완료까지 시간, 도움 요청, 반복 검색, 오해, 실패 위치를 `usability-results.csv`에 기록합니다. 직접 조회와 추천 과업은 동일 난이도의 다른 조건을 사용하고 참여자마다 순서를 바꿉니다.

| ID | 역할 | 과업 | 성공 판정 |
| --- | --- | --- | --- |
| U01 | 학생 | 비로그인 상태로 장비·시설 담기 후 가입·제출 | 선택 유지, 별도 최종 확인, 신청 번호 확인 |
| U02 | 학생 | 직접 조회로 회의 6명에 필요한 공간과 장비 찾기 | 인원·허용 용도·시간을 만족하는 항목 선택 |
| U03 | 학생 | 같은 수준의 활동을 목적별 추천으로 준비 | 추천 이유를 이해하고 적합 자원 선택 |
| U04 | 학생 | 사용 불가 자원의 다른 일정·대체 자원 찾기 | 일정 유지 조건 이해, 최초 희망과 최종 선택 확인 |
| U05 | 학생 | 자신의 대기 신청 취소, 타인 내역 접근 시도 | 본인 대기만 취소, 타인 개인정보 미노출 |
| U06 | 관리자 | 대기 신청 승인·거절, 다른 창에서 오래된 상태 처리 | 거절 사유·예약 확보 이해, 중복 처리 차단 |
| U07 | 학생·관리자 | 출고→일부 반환→보류→추가 반환→완료 | 출고 기준·누적 수량·보류 사유 이해 |
| U08 | 관리자 | 시설 이용 시작·종료 및 운영 조건 편집 | 실제 이용 시각 확인, 기존 승인 예약 보호 |
| U09 | 관리자 | 모델·사양 수정, 대체 관계 해제, 시설 제한 해제 | 카탈로그 반영, 변경 이력 확인 |
| U10 | 학생 | 모바일에서 신청 내역 확인 후 재로그인 | 가로 넘침 없이 주요 버튼 사용, 저장 이력 유지 |
| U11 | 관리자·학생 | 손상 구성품 메모·부분 반환 보류 후 추가 반환, 회차 상세 확인 | 손상 메모가 이전 회차에 남고 누적 반환과 점검 상태를 이해 |
| U12 | 관리자 | 승인된 장비의 현장 출고를 사후 등록 | 실제 시각·등록 시각·사유·전달 수량을 구분, 중복 기록 차단 |

과업 후 적합성·쉬움·조건 이해도를 각각 1~5점과 자유 의견으로 받습니다. 실패는 진행자가 도와 완료한 결과와 독립 완료를 구분합니다. 실제 결과를 수집한 뒤 완료율·중앙 소요 시간·반복 검색 수를 계산하고 발견 문제→수정→재시험을 기록합니다. 표본이 작으면 전체 학생에 대한 효과로 일반화하지 않습니다.

데이터는 시험 자산·신청 번호로 식별하고 실명·비밀번호는 기록하지 않습니다. 시험 신청은 정상 취소·거절·반납·이용 완료로 정리하며 자산은 중지·품목 비활성으로 처리합니다. 기록 삭제는 별도 요청 범위 확인 후 진행합니다.
