# 2026-11-18 순차 검증·관리자 기능 구현

사용자 요청에 따라 안정성 시험 → 장비 관리(F08) → 대체 관계 관리(F17) → 시설 운영 관리(F21)를 진행했습니다. 로컬 코드를 수정했으며 Git Commit/Push는 하지 않았습니다. 실제 DB 자격정보는 기록하지 않습니다.

## 안정성 검증

- 두 독립 트랜잭션을 동시에 시작해 같은 장비·기간의 승인 한 건만 커밋되는지 확인했습니다. 시험 신청은 반납 완료·취소로 정리합니다.
- 묶음 신청의 첫 항목 입력 후 다음 항목의 정원 검증을 실패시켜 묶음·항목·상태 이력 전체 롤백을 확인했습니다.
- 신규 시험 행에 DB CHECK 위반을 발생시켜 동일 트랜잭션의 앞선 입력이 모두 롤백되는지 검사하는 시험을 추가했습니다.
- 별도 로컬 서버를 실제 종료·재시작해 계정과 신청이 유지되고 이전 로그인 세션은 만료되는지 확인했습니다. 시험 신청은 취소했습니다.
- 운영 DB 연결을 끊거나 다른 팀 세션을 종료하지 않았습니다. 실제 네트워크 단절·시간 초과·운영 장애 주입은 별도 환경에서 시험해야 합니다.

## 구현 범위

| 기능 | 화면 | 동작 |
| --- | --- | --- |
| F08 | /admin/equipment | 기존 모델 선택, 관리번호·이름·장소·부서·허용 여부·운영 상태·기본 구성품 등록/수정 |
| F17 | /admin/alternatives | 같은 품목의 원래→대체 방향, 이유·주요 차이·적용/해제 등록/수정 |
| F21 | /admin/facilities | 시설 등록/수정, 정원·목적·요일별 시간·운영 상태, 제한 일정 등록/수정 |

장비·시설 자체와 신청·출고·반납 이력을 삭제하는 API는 추가하지 않았습니다. 기본 구성품·요일·허용 목적은 정의 변경 시 같은 트랜잭션에서 교체하지만 과거 출고 스냅샷은 수정하지 않습니다. 대체 관계는 비활성화로 해제합니다. 시설 제한은 수정만 지원하며 취소/삭제용 ERD 컬럼을 임의 추가하지 않았습니다.

승인·미반납 장비의 모델 변경·이용 중지와 기존 승인·이용 중 시설 예약에 충돌하는 정원·목적·시간·중지·제한 변경을 차단합니다. 자원 잠금·버전으로 저장 충돌을 검사하며 대체 관계는 이전 필드값을 대조합니다. 요일별 시설 시간은 일반 조회·대체 일정 검색에도 반영됩니다.

기존 품목·모델·사양 정의 자체의 편집, 충돌 예약의 자동 취소·대체·알림, 시설 제한 수정의 별도 감사 이력은 후속 범위입니다.

## 검증 및 DB 영향

- 기존 Oracle 업무 통합 시험 7개와 새 관리자 Oracle 통합 시험 7개가 통과했습니다. 관리 시험의 행 변경은 롤백합니다.
- 관리자 브라우저 검사 11개가 통과했습니다. 장비 등록·수정·관계 해제·시설과 요일별 시간·제한 일정 반영을 확인했습니다.
- 브라우저 시험 중 장비 2개·시설 1개를 등록했습니다. 검증용 이름으로 구분했고 종료 시 이용 중지했으며 대체 관계도 해제했습니다. 시험 자원·검증 계정·완료 또는 취소 신청은 이력으로 남습니다.
- 기존 흐름 회귀 중 빠른 저장·로그아웃·로그인 조작에서 CSRF 토큰이 엇갈리는 UI 문제가 드러나, 로그인·업무 저장·재조회가 모두 끝난 뒤 대화상자를 닫도록 수정했습니다. CSRF 검사는 유지합니다.
- 서로 같은 장비를 쓰는 브라우저 시험과 동시 승인 시험은 병렬 실행하지 않고 순서대로 실행합니다.

powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-restart.ps1

## 후속 보완: 요구사항 매핑·관리 상세·시험 및 배포 준비

앞 단락의 스키마 유지는 기본 관리 기능까지의 기록입니다. 후속 작업에서는 기존 이름을 유지하며 `10_block_audit.sql`을 실제 DB에 1회 적용했습니다. FACILITY_BLOCK에 해제 관련 컬럼 4개를 추가하고 `TBL_FACILITY_BLOCK_LOG`, `SEQ_FACILITY_BLOCK_LOG`와 제약·인덱스를 생성했습니다. 기존 제한은 IMPORT 기준 기록만 남기며 과거 이력을 재구성하지 않습니다. 읽기 전용 11번 검증으로 테이블 27개·컬럼 198개·시퀀스 18개를 확인했습니다. 원본 ERD 수정 반영은 별도 필요합니다.

- 품목·모델·사양 항목·사양값 등록/수정 화면·API, revision 충돌 검사와 진행 중 대여 보호를 추가했습니다. 품목 비활성 후에도 자산은 과거 내역 조회용으로 유지하고 새 신청은 차단합니다.
- 시설 제한 등록·수정·해제 시 전후 값·사유·담당자·시각을 같은 트랜잭션으로 남깁니다. 해제된 일정은 공개 예약·신청 가능 검사에서 제외합니다. 관리자에게 변경 이력을 제공합니다.
- 직접 조회/추천/대체 선택 경로, 활동 텍스트와 최초 희망 자원·기간을 저장하고 본인·관리자 내역에 표시합니다. 다른 일정의 이용 길이와 지정 대체 장비 방향을 서버에서 검사합니다.
- 요구사항 F01~F29를 [대응표](../requirements-status.md)에 정리했습니다. 구성품별 손상·검수 메모·회차 상세·사후 출고 등록과 선택 기능은 완료로 표시하지 않았습니다.
- 실제 참여자용 과업과 빈 결과 CSV, 배포 문서·외부 비밀 설정/서비스/HTTPS 프록시 예시·허용 파일만 묶는 패키징 스크립트를 준비했습니다. 실제 사용자 시험·외부 서버 배포는 수행하지 않았습니다.
- 이력 증가 시 신청마다 수행하던 상태 로그·출고·반환·원래 선택 조회를 권한 범위의 일괄 조회로 바꾸었습니다. 화면 회귀 검사 시간 초과 후 개선한 사항입니다.

실제 계정·비밀번호는 출력하지 않고 Git 제외를 유지합니다. 후속 변경은 로컬에서 작성했으며 Commit/Push하지 않았습니다.

후속 검증 결과: 업무 Oracle 시험 7개·관리 Oracle 시험 10개가 모두 통과했고 행 변경은 롤백했습니다. 최종 빌드에서 기존 신청·승인·출고·반납 브라우저 검사 11개가 통과했습니다. 관리자 검사는 품목·사양·모델 저장과 제한 해제·이력을 포함해 최종 빌드에서도 20개가 통과했습니다. 브라우저 시험 자원은 중지·관계 해제·품목 비활성으로 정리하며 이력은 남습니다.

배포 패키지 `.work/releases/campusrent-20261118-115728-bd61b9.zip`을 생성했습니다. ZIP과 내부 애플리케이션 JAR의 로컬 설정 제외 및 실제 DB 계정·비밀번호 부재를 검사했습니다. 배포 패키지는 외부에 전송하지 않았으며 서버 OS·접속 방법·도메인, 사용자 시험 참여자·일정은 아직 미확정입니다.

## 구성품 손상·검수 회차 상세·사후 출고 등록

사용자 요청 순서대로 F10·F11·F12의 남은 검수 기능을 구현했습니다. 기존 RETURN_COMPONENT의 RETURN_CONDITION·NOTE_TEXT, CHECKOUT의 SOURCE_CODE·ACTUAL_CHECKOUT_AT와 상태 로그를 사용하며 DDL·설치 SQL은 실행하지 않았습니다.

- 이번 반환 수량별 정상·손상·미반납과 구성품 메모를 입력합니다. 손상에는 메모를 요구하며 반환량과 맞지 않는 상태·초과 반환·부족 상태 완료는 차단합니다.
- 손상 또는 점검 요청이 있으면 장비 상태·점검 로그를 동일 트랜잭션으로 저장합니다. 이전 손상 기록은 추가 반환으로 지워지지 않고 별도 관리자 점검 완료가 필요합니다.
- 학생 본인과 관리자가 출고 당시 기준, 실제/등록 시각·담당자·사유, 회차별 반환·누적량·상태·메모·검수자·시각을 상세 창에서 조회합니다. 타인·비로그인 접근은 서버에서 차단합니다.
- 승인된 장비 신청의 사후 출고는 실제 시각·필수 사유·당시 전달 수량·상태·메모를 입력합니다. 실제 시각은 과거로 기록하지만 등록·상태 변경 시각은 현재로 남깁니다. 중복 등록·미래 시각·기존 실제 대여 구간 중복을 차단합니다. 이미 출고한 기록을 덮어쓰지 않습니다.
- Oracle 통합 시험은 기존 17개와 신규 검수 시험 7개, 총 24개가 통과했습니다. 시험 데이터 변경은 롤백했습니다. 기존 테이블·시퀀스 이름은 그대로 유지합니다.

현재 구성품 정의를 확인하여 사후 전달 수량·상태를 입력하는 방식입니다. 승인되지 않은 임의 대여나 삭제된 과거 구성품을 복원하는 기능은 포함하지 않습니다. 현장 손상 판정·사후 등록 허용 기간 등 실제 운영 정책과 사용자 검증은 별도로 확정합니다.

검수 브라우저 검사 12개가 통과했습니다. 전용 시험 자산으로 신청→승인→사후 출고→손상·부분 반환 보류→추가 반환→본인 회차 조회→점검 완료를 확인했습니다. 시험 자산은 이용 중지하고 이력은 보존했습니다. 새 배포 패키지 `.work/releases/campusrent-20261118-121351-683b8f.zip`에도 실제 DB 계정·비밀번호·로컬 설정이 포함되지 않았음을 검사했습니다. 서버는 로컬 127.0.0.1:8080에서 실행하며 외부 배포·Git Commit/Push는 진행하지 않았습니다.

최종 일반 업무 브라우저 회귀 검사 11개도 통과했습니다. 이번 검증은 Oracle 통합 24개와 브라우저 23개(검수 12개·기존 업무 11개)이며, 실제 사용자 과업 시험과 구분합니다.

## 인증 보안→DB 장애 대응→조회 성능→운영 준비

사용자가 사용자 과업 시험을 일부 진행했다고 알려주었고, 시스템 보완을 순서대로 요청했습니다. 결과 수치는 전달받지 않아 사용자 시험 CSV에 기입하지 않았습니다.

1. 인증: 로그인·가입·비밀번호 변경 시도 제한, HTTP 429·Retry-After, 미등록 계정도 비밀번호 해시 검사 비용을 거치는 처리, 12자 이상 가입/변경 비밀번호, 현재 비밀번호 검증 후 해시 변경·동일 사용자 세션 종료를 구현했습니다. production 프로필에서는 시연 계정 차단·Secure 쿠키·loopback 바인딩을 요구합니다. 실제 운영 관리자 지정이나 기존 시연 비밀번호 변경은 하지 않았습니다.
2. DB 장애: 연결·읽기·쿼리·트랜잭션 대기 시간을 설정하고 연결 장애·시간 초과·충돌을 503/504/409로 구분합니다. 오류 본문·로그에 DB 계정·SQL·비밀번호를 노출하지 않고 reference를 반환합니다. 새 신청은 UUID 키를 저장하고 기존 고유 신청번호·사용자 잠금으로 중복 재시도를 방지합니다. 기존 CR-번호·테이블·시퀀스는 유지하고 DDL·설치 SQL은 실행하지 않았습니다.
3. 조회: Oracle 11g ROWNUM으로 최신 신청 ID를 페이지 처리하고 해당 페이지의 이력·출고·대체 조건만 조회합니다. 학생 소유권은 모든 쿼리에 유지합니다. 기본 25건, 최대 100건과 진행/과거 필터·이전/다음 버튼을 제공합니다. 전체 28건 당시 기본 페이지의 3회 측정 중앙값은 약 156ms였습니다. 대량 부하 검증으로 해석하지 않습니다.
4. 운영: live/ready·읽기 응답 측정 도구, 로그 회전 설정, 읽기 전용 복원 검증 SQL·백업/복구 절차·생산 설정 검사를 준비했습니다. 공식 Spring/Oracle 문서에서 유지보수·호환 요구를 확인하여 업그레이드 검토를 기록했으며 기존 Java 8·Oracle 11g 환경의 버전을 임의로 변경하지 않았습니다.

## 과제·유튜브·면접 등 추천 인식 확장

사용자 요청에 따라 추천 목적 7개·활성 키워드 214개로 확장했습니다. 기존 목적 4개와 관련 신청은 유지하고 영상 콘텐츠 촬영·면접 연습·과제·학습을 추가했습니다. `recommendation-seed.json`에서 생성한 `12_recommendations.sql`을 한 트랜잭션으로 적용했습니다. 기존 테이블·시퀀스 이름을 유지하며 DDL·삭제·전체 설치 실행은 하지 않았습니다. 새 시설 허용 목적은 코드와 IS_DEMO_YN이 일치하는 원래 시연 시설에만 추가하고 버전을 갱신했으며 실제 시설에는 일괄 적용하지 않았습니다.

목적·키워드·장비 규칙을 Oracle API에서 읽도록 교체하고, 관리자 키워드 등록·수정·해제·검색과 오래된 창 수정 차단을 구현했습니다. 새 목적·장비 규칙 자체의 관리 UI는 이번 범위에 포함하지 않습니다. 과제 발표·과제 영상·보고서·자료 조사·캡스톤·졸업 작품·스터디·시험 공부를 구분하고 PT 면접·유튜브 시청·촬영 없이·카메라/마이크 제외 등을 문맥으로 검사합니다. 불명확한 과제·복수 목적은 선택하게 합니다. 존재하지 않는 품목·중지 장비도 화면 오류 없이 처리합니다.

검증: 기존 Oracle 통합 28개와 추천 통합 4개, 단위 9개가 통과했습니다. 추천 브라우저 검사 64개에서 예문·부정·복합 표현·인원·실제 추천 화면·DB 키워드 추가/해제를 확인했습니다. 추가한 브라우저 시험 키워드는 해제 상태로 보존했습니다. 검증 중 외부 Oracle 접속 시간 초과가 발생했으나 준비 상태 복구를 확인한 뒤 재검사했습니다. 실제 학교 운영 허가나 모든 자연어 의미 인식을 보장하는 기능으로 표시하지 않습니다.

사용자는 로컬 서버를 새로고침하여 ‘유튜브 촬영’, ‘면접 연습’, ‘레포트 작성’, ‘과제 영상 촬영’ 등으로 확인할 수 있습니다. 상세 내용은 [추천 안내](../recommendations.md), 초기 SQL 적용은 [DB 안내](../../db/oracle11g/README.md)를 참고하세요. Git Commit/Push는 진행하지 않았습니다.

최종 기존 업무 브라우저 회귀 11개와 관리자 관리 회귀 20개도 통과했습니다. 추천 64개와 합쳐 이번 브라우저 검증은 95개입니다. 배포 패키지 `.work/releases/campusrent-20261118-130325-f6244d.zip`을 갱신하고 실제 DB 계정·비밀번호·로컬 설정이 없는지 검사했습니다. 기존 패키지와 마찬가지로 설치 SQL은 포함하지 않으며 다른 DB 환경의 추천 초기 데이터 적용은 12번 SQL을 별도로 검토해야 합니다.
