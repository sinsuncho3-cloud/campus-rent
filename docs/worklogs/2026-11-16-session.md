## 현재 개발 구조

- 화면: `src/main/resources/templates/index.html`, `static/`의 HTML·CSS·JavaScript.
- 미리보기: `tools/PreviewServer.java`, `preview.cmd`; Java 8 기반 정적 HTTP 서버.
- 브라우저 시연: 로그인은 메모리, 선택 목록은 sessionStorage, 신청·검수는 IndexedDB.
- Oracle 연결 점검: `tools/OracleConnectionCheck.java`, `check-oracle.cmd`.
- JDBC 준비: `tools/setup-oracle-jdbc.ps1`; 드라이버는 Git 제외 경로 `.work/jdbc/`에 저장.
- Spring Boot·서버 인증·업무 API·화면의 실제 DB 연동은 아직 미구성.

## DB 연결 및 보안 결정

- 현재 Java 8을 유지하고 Oracle JDBC Thin으로 제공된 호스트·포트·SID에 접속합니다.
- 실제 스키마 계정과 비밀번호는 사용자가 `src/main/resources/application-local.properties`에 직접 입력했습니다. 파일 내용과 자격정보는 기록·출력하지 않습니다.
- 로컬 properties, `.env`, `.env.*`, `.work/`는 Git에서 제외합니다. 예시 설정에는 실제 계정·비밀번호를 넣지 않습니다.
- 초기 APP_USER 시연 계정 SQL은 실제 DB 접속 계정과 별개입니다. 아직 DB에 입력하지 않았습니다.
- 기존 테이블명과 `SQ_` 시퀀스명을 유지합니다. `TBL_`·`SEQ_` 규칙 적용을 위해 임의로 변경하지 않습니다.
- GitHub 웹페이지에 직접 로그인해서 파일을 수정하지 않습니다. VS Code 작업 폴더의 로컬 파일을 수정하고 로컬 Git 명령으로 커밋·푸시합니다.

## ERD 및 생성 전 검토

- 기준 파일: `docs/erd/[New-Era] CampusRent_ERD_20261020.pdf`. 계획서에는 초안으로 표기되어 있으며 별도의 확정본은 발견하지 못했습니다.
- 테이블·컬럼명, 자료형·길이·NULL 허용 여부, 단일·복합 PK와 FK 참조 구조를 대조했습니다.
- 시퀀스는 ERD에 직접 명세되어 있지 않아 SQL의 17개를 단일 숫자 PK 발급 설계로 검토했습니다.
- 실행 SQL에서 DROP·TRUNCATE·DELETE는 발견되지 않았습니다. 주석의 관련 단어와 실제 실행문을 구분했습니다.
- `07_queries.sql`은 변경문도 포함한 참고 자료이고, `09_verify.sql`은 시험 입력·롤백·시퀀스 증가가 있어 읽기 전용이 아닙니다.
